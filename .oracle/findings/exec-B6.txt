## Deviations / observations for oracle
1. useDataLanes uses `useOptionalVideoEditorRuntime()` (null-safe) rather than
   the throwing `useVideoEditorRuntime()` — same runtime source, but bare-canvas
   test environments and non-editor mounts fail open to empty lanes.
2. DataLaneRow passes boundary `kind="slot"` (no `dataLane` member exists in
   ErrorBoundaryContributionKind; that union lives in ContributionErrorBoundary,
   outside batch scope).
3. FOUND DEFECT (pre-existing, NOT fixed — assembleDataLanes.ts is Batch 4's
   file): `mergeDataLanes` return type `TimelineData & { readonly dataLanes:
   readonly DataLaneView[] }` no longer typechecks after B5 made
   `TimelineData.dataLanes` mutable — TS2322 at assembleDataLanes.ts:155.
   One-line fix for the rework flow: return type plain `TimelineData`
   (intersection is now redundant). Flagged for B9's typecheck gate.
4. Registry context gap (wave-level, not batch-level): DataKindRegistryProvider
   is not mounted anywhere in the tree (editorRuntimeAssembly owns the registry
   instance via dataKindRegistryRef; no lifecycle component bridges it into
   context the way RuntimeClipTypeRegistryLifecycle does for clipTypes).
   Consequence: in the running editor today every assembled lane renders OPAQUE
   (host extent bars); registered-kind renderer lanes display only under a
   provider (tests prove that path). B8's done-4 dev example will need the
   provider mounted + bridged to dataKindRegistryRef to show renderer output.
5. mobile-interaction-conformance.test.tsx fails identically (77) on
   pre-batch HEAD — pre-existing selectionStore mock gap, unrelated.
