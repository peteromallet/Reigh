## Test-doubles findings (ranked)

**1. 114 test files hand-roll PostgREST chain mocks bound to supabase-js — all die at C-1.**
Every hook/repo test does `vi.mock('@/integrations/supabase/client')` with ad-hoc `from().select().eq().single()` chains (e.g. `src/shared/hooks/shots/__tests__/useShotImages.test.ts:7-21`, `src/domains/generation/hooks/__tests__/useGenerationMutations.test.ts:7-16`; 114 files match). No shared builder exists; each file re-implements the chain, so cutover means ~114 rewrites unless a seam is provided first.

**2. Good seam already exists for providers — reuse it.**
`runProviderCompatibilitySuite` (`src/tools/video-editor/testing/providerCompatibility.shared.ts:78`) runs the same CAS/load/save battery against InMemory/Supabase/AstridBridge/Browser factories; `InMemoryDataProvider` + `coreTestPorts.ts:36` are clean doubles. This is the model to extend, not replace.

**3. Bridge-side doubles are timeline-only; covered-journey routes absent.**
`bridgeContract.ts` (zod, `:51-83`) covers timeline payloads only. The e2e stub `tests/e2e/timeline/astrid-bridge-stub.mjs:101-199` implements health/projects/timelines/save(CAS)/registry/assets+Range but **no tasks (B-routes), gallery (R12), or media-content (R9)** routes that the acceptance journey needs. `real-bridge-serve.mjs` boots real `astrid serve` for the same specs.

**4. `src/test/test-utils.tsx` accepts auth/project context options it silently ignores** — `_authValue`/`_projectValue` assigned then unused (`:59-60`); wrapper renders only QueryClientProvider. Misleading surface; trim during cutover.

Delete PostgREST mocks per-module at cutover; no new framework (no MSW).
