## VERDICT: FAIL

One high-severity defect: the B7 interaction→inspector loop cannot fire end-to-end in production. Everything else holds.

### Findings

**H1 — Inspector dispatch is unreachable (two independent breaks; tests mock the broken seam).**
- *No producer:* nothing ever creates a `dataItem`/`dataLane` interaction target. `DataLaneRow`/`DataLaneList` contain zero pointer/click handlers; `TimelineCanvas` never calls `setInspectorTarget` with a data target. The kinds exist only in `mobile-interaction-model.ts`, `extensionSurface.ts` (`TargetContextPayload`), and `PropertiesPanel`'s reader branch.
- *No resolvable consumer:* `PropertiesPanel.tsx:257-271` resolves `selectedDataItemView` from `useTimelineEditorData().data.dataLanes` — the **store's** TimelineData. By Batch-5 design `mergeDataLanes` is render-side only and the store is never written, so live `dataLanes` is always the frozen empty default. Even with a producer, neither a kind's bound inspector nor `OpaqueDataItemInspector` could ever mount.
- Both unit suites pass only because `PropertiesPanel.test.tsx:930-943` hand-injects lanes into mocked store data and hand-sets targets. This is precisely the brief's "hollow success" pattern for the inspector half. Lane *rendering* is NOT theater (see below). Fix without violating duration-neutrality: share the patched lane plane via context (or have the panel consume `useDataLanes`), and add row/item press handlers that set targets from `lane.items`.

**M2 — Renderer `domain` can silently lie.** `DataLaneView` carries no `domain`; `DataLaneRow.paintLane` re-looks it up from the registry snapshot with fallback `'timeline_seconds'`. If a kind is unregistered while stale assembled lanes still render, the renderer receives a wrong domain; the inspector path uses `item.domain`. Put `domain` on the view at assembly time.

**L3 — Ordinal nit in pinned test.** `boundary.test.ts`: "22 kinds (dataKind is kind 22)" — dataKind is entry 21 of 22 (reserved `agent` is 22nd). Count pin correct; parenthetical wrong.

**L4 — Fetch-dedupe outlives loader swap.** `useDataLanes.requestedRef` persists across `effectiveLoader` identity changes; a mid-mount runtime/resolver replacement never refetches already-requested assets. Documented as per-mount cache; acceptable V1, worth a comment-to-code link.

**L5 — Duplicated [CONVERGE-WITH-M1] vocabularies with no drift guard.** `DataShape`/`DataCoordinateDomain` defined identically in `sdk/video/families/dataKind.ts` and `data/typed/envelope.ts`; `'reigh.transcript_segment/v1'` duplicated host/extension (deliberate import isolation). All flagged, currently identical, but nothing fails if they diverge. Cheap fix: a type-equality assertion test.
