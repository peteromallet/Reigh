### HIGH

**1. Schema is test-only; loader never fail-closes unknown collections.**  
Ajv `additionalProperties: false` lives in `manifest-schema-validation.test.ts` (`validateFn` ~50–51, `dataProviders` ~524–536). Load path is only `validateManifest` (`extensionPackageManifest.ts:247`, `extensionLoader.ts:1086–1127`). `validateManifest` never walks unknown keys (`manifest.ts:321–768`). So `{ dataProviders: [] }` **loads**. Design’s fail-closed proof is a unit-test ghost.  
**Fix:** run compiled schema at `validate()` (or reject unknown keys in `validateManifest`); add a loader test that a top-level `dataProviders` pack is `valid: false`.

**2. Permission contracts are mutually incompatible.**  
TS: `{ reason, posture?: { network, filesystem, env, processes } }` (`manifest.ts:216–226`). Schema: `{ permission?, reason? }`, no `posture`, `additionalProperties: false` (`reigh-extension.schema.json:997–1004`). `validateManifest` ignores `permissions`. Runtime never consults them (`ExtensionTrustWarningBanner.tsx:16`). Wiring Ajv into the loader (finding 1) would **reject** real TS-shaped permissions.  
**Fix:** one shape (keep `posture`, drop stray `permission`); validate in both Ajv and `validateManifest`; keep the banner.

**3. `apiVersion` is optional and unenforced.**  
Schema: optional integer ≥1 (`schema.json:31–35`). Validator only checks if present (`manifest.ts:390–394`). Host always stamps `ctx.apiVersion: 1` (`extensionContextFactory.ts:459`). No host/extension compatibility gate.  
**Fix:** require `apiVersion` in installed mode; reject ≠ host version.
